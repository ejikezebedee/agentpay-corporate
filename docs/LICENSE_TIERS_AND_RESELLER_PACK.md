# Open-Source Commercial Services Pack

Use this pack to explain how AgentPay Corporate can remain open source while still supporting paid implementation, support, customization, hosting, training, and launch-readiness services.

This is plain-language commercial guidance, not legal advice. The project code is governed by the MIT License in `LICENSE`.

## License Summary

AgentPay Corporate uses the MIT License.

Allowed under MIT:

- Use the project for personal, business, client, educational, or public demo work.
- Copy, modify, publish, distribute, sublicense, and sell copies of the software.
- Fork the repository and build customized versions.
- Sell services around setup, customization, deployment planning, training, hosting, security review, or compliance-readiness planning.

Required under MIT:

- Include the copyright and permission notice in substantial copies of the software.

Not allowed by project policy or safety positioning:

- Claim AgentPay Corporate is a licensed financial product.
- Claim it processes live payments out of the box.
- Hide production warnings when real wallet, escrow, payment, customer-data, or settlement workflows are involved.
- Include real credentials, private keys, customer data, or private server paths in public releases.

## Paid Service Offers

### Setup Review

Best for:

- Founders who want help previewing the website and console.
- Developers who want a guided backend starter check.
- Agencies preparing a client demo.

Typical deliverables:

- Local preview check.
- File-structure walkthrough.
- Backend starter test review.
- Production-boundary explanation.

### Brand Customization

Best for:

- Agencies and founders adapting the public website.
- Teams preparing investor or customer demos.

Typical deliverables:

- Logo and color replacement.
- Homepage copy edits.
- Pricing and marketplace sample updates.
- Screenshot refresh after customization.

### Implementation Planning

Best for:

- Teams moving from prototype to MVP planning.
- Buyers who need backend, database, or API architecture guidance.

Typical deliverables:

- Backend gap review.
- Database and API launch plan.
- Security and compliance-readiness checklist.
- Production stop-condition review.

### Managed Deployment Or Hosting

Best for:

- Teams that want someone to deploy the static frontend or plan the API environment.

Typical deliverables:

- Static hosting setup.
- Environment checklist.
- DNS and launch-control review.
- Rollback plan.

## Service Decision Tree

- Wants the public code: use the open-source repository/archive.
- Wants help opening or testing it: offer setup review.
- Wants brand/client changes: offer customization.
- Wants real backend planning: offer implementation planning.
- Wants live payment movement: require legal, compliance, security, infrastructure, and launch-control work before activation.

## Marketplace Wording

Short version:

AgentPay Corporate is open source under the MIT License. The code can be used, modified, and redistributed under the license. Paid offers cover setup help, customization, hosting, implementation planning, and production-readiness support.

Long version:

AgentPay Corporate is an open-source website, MVP console, backend starter, database schema, OpenAPI contract, and launch-control kit for agentic commerce workflows. The project is not a licensed payment processor and does not process live payments out of the box. Paid commercial value comes from support, customization, deployment planning, backend hardening, and compliance-readiness services.

## Service Quote Notes

When quoting paid work, define:

- Exact deliverables.
- What files or environments will be changed.
- Whether deployment is included.
- Whether backend implementation is included.
- Whether payment-provider setup is included or excluded.
- Whether legal, compliance, privacy, or security review is included or referred to qualified professionals.
- Response time and support window.
- Acceptance checklist.

## Redistribution Risk Controls

Even with MIT redistribution rights:

- Keep safety disclaimers.
- Disclose that AgentPay is not a live payment processor.
- Do not imply legal, financial, regulatory, or compliance approval.
- Do not ship real credentials, private keys, customer data, or private operational paths.
- Do not use AgentPay branding to imply official endorsement of modified forks.

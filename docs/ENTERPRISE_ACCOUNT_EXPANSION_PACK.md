# Enterprise Account Expansion Pack

## Purpose

Use this pack after a buyer, pilot sponsor, agency client, partner lead, or enterprise stakeholder has already reviewed AgentPay and needs a structured path from first interest to expansion, renewal, internal rollout, or paid implementation planning.

The goal is to help sellers and agencies grow account value without promising that AgentPay is already a regulated, production-ready payment system.

## Expansion Positioning

AgentPay can expand from a demo package into several buyer-side workstreams:

- Executive demo and internal stakeholder review.
- Brand-customized prototype for a board, investor, client, or pilot sponsor.
- MVP planning workshop with roadmap, backlog, and implementation scope.
- Procurement, privacy, compliance, and security review preparation.
- Paid pilot planning with success criteria and production stop conditions.
- Production backend planning after legal, compliance, security, and payment-provider review.
- Maintenance, update, training, and customer success support.

Do not describe expansion as automatic production launch. Every expansion offer must keep real payment handling behind production launch-control gates.

## Expansion Discovery Questions

Ask these before proposing a larger engagement:

- Who will use AgentPay: founder, agency team, client team, pilot users, operators, or developers?
- Is the immediate goal demo, validation, procurement, pilot, implementation planning, or production build?
- Which workflows matter first: wallet, seller tools, escrow, marketplace, API keys, admin review, support, onboarding, or reporting?
- Is real payment movement planned now, later, or not at all?
- Who owns legal, compliance, security, privacy, and payment-provider review?
- What internal approval is needed before paid implementation or pilot work?
- What is the expected timeline for review, pilot, decision, and rollout?
- What budget range exists for customization, implementation planning, backend build, support, or maintenance?

## Expansion Offer Ladder

| Offer | Scope | Boundary |
| --- | --- | --- |
| Setup walkthrough | Archive review, local preview, checklist, and questions | No customization or production work |
| Executive demo pack | Demo flow, screenshots, briefing notes, stakeholder questions | No live transaction claims |
| Brand-customized prototype | Copy, brand assets, example listings, screenshots, handoff notes | Static/demo package only unless separately scoped |
| Pilot planning workshop | Validation scorecard, pilot scope, success criteria, feedback log | Pilot does not process real payments unless production gates are complete |
| Implementation planning sprint | Backlog, API/database review, deployment path, quote, SOW | Planning only until backend contract is approved |
| Enterprise review support | Procurement, privacy, security, compliance, evidence map | Not legal, tax, or regulatory advice |
| Support and maintenance retainer | Updates, training, triage, release notes, recurring review | Does not include emergency production incident ownership unless separately contracted |
| Production advisory | Launch-control review, payment-provider readiness, audit-log planning | Production activation requires separate approval and qualified review |

## Expansion Risk Controls

| Risk | Control |
| --- | --- |
| Buyer expects live payment processing after demo | Repeat production launch-control boundary in every expansion note |
| Stakeholders have different expectations | Use stakeholder map and account tracker before quoting |
| Pilot expands into regulated production work | Require legal, compliance, privacy, security, and payment-provider gates |
| Agency overpromises delivery timeline | Use implementation scope, change-control, and handoff packs |
| Support retainer becomes production incident ownership | Define support exclusions and incident scope before retainer start |
| Procurement treats demo docs as certification | Use due-diligence and risk disclosure language only |

## Final Expansion Checklist

- Current account stage is identified.
- Primary and secondary stakeholders are listed.
- Immediate buyer goal is documented.
- Expansion offer is matched to the buyer stage.
- Required reference packs are selected.
- Production payment intent is recorded.
- Compliance, security, privacy, and legal review owners are identified when needed.
- Real payment activation remains outside scope until launch-control gates are complete.
- Follow-up email is sent with next decision, open risks, and boundary language.
- Account expansion tracker is updated before the next call or quote.
